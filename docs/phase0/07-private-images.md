# 07｜私有 PNG 儲存、解鎖驗證與授權讀取設計

## 1. 目標

- 正式角色插畫**不可公開取得**：沒有解鎖的人，即使猜到檔名也拿不到。
- 未解鎖圖鑑只用剪影。
- 已解鎖玩家可在圖鑑、詳情頁、分享功能中使用正式插畫。

## 2. Bucket 規劃

| Bucket | 公開 | 路徑格式 | 內容 |
|---|---|---|---|
| `character-art` | **否** | `{character_id}/full.png` | 正式透明 PNG |
| `character-art` | **否** | `{character_id}/thumb.webp` | 圖鑑縮圖（選用，可減少流量） |
| `silhouettes` | 是 | `{character_id}.png` | 剪影 |
| `brand` | 是 | `logo.png` 等 | 法鬥好朋友 Logo、收藏卡底圖 |
| `avatars` | 否 | `{user_id}/avatar.webp` | 玩家頭像 |

> 路徑使用 `character_id`，不使用圖鑑編號或角色名稱，避免從檔名推測內容。
> 剪影路徑也使用 `character_id`；若連「有哪些角色 ID」都要保密，可改用隨機檔名（D-10 相關）。

## 3. 授權讀取機制

使用 **Supabase Storage RLS + 簽名網址（Signed URL）**，不需另外架設伺服器：

```text
character-art 的 SELECT policy（設計，非正式 SQL）：
  允許 authenticated 讀取 storage.objects，條件是
    bucket_id = 'character-art'
    且 路徑第一層資料夾（character_id）
       存在於 player_collection 中 user_id = auth.uid() 的列
```

流程：

1. 前端呼叫 `createSignedUrl('character-art', 'fm001/full.png', 有效秒數)`。
2. Storage 以該玩家身分檢查 policy → 有解鎖才簽發。
3. 前端用回傳的網址顯示圖片；網址到期後失效。

### 已知限制（請知悉）

- 簽名網址在有效期內**任何人拿到都能開**。玩家若把網址轉貼，別人在到期前可以看到。縮短有效期可降低風險。
- 已解鎖玩家本來就能下載透明 PNG 並分享，所以「保護」的目標是**未解鎖者無法透過系統取得**，不是防止已解鎖者轉傳。
- 解鎖狀態以資料庫為準；訪客只能試玩（D-12），不會有任何解鎖紀錄。

## 4. 快取策略（待決策 D-21）

簽名網址每次產生都不同，瀏覽器無法以網址快取，需要另外設計：

| 選項 | 說明 | 優點 | 缺點 |
|---|---|---|---|
| A. 短效（例 5 分鐘）＋記憶體快取 | 同一次開啟 App 內重複使用網址 | 最安全 | 每次開 App 重新下載圖片，流量較高 |
| B. 中效（例 1 小時）＋記憶體快取 | | 流量與安全平衡 | 轉貼網址可用 1 小時 |
| C. 短效網址＋圖片存入 IndexedDB／Cache Storage | 下載後存在玩家裝置 | 流量最低、離線可看 | 實作較複雜；需處理容量與清除 |
| D. 長效（例 7 天） | | 最簡單 | 轉貼網址可用很久 |

秒數皆為示範，實際值待你決定。

## 5. 分享功能與圖片

- 收藏卡在前端用 Canvas 合成：正式插畫＋角色名稱＋編號＋暱稱＋頭像＋品牌 Logo。
- Canvas 讀取跨網域圖片需要 CORS；Supabase Storage 支援，Phase 3 需實測確認不會造成 Canvas 污染（tainted canvas）而無法匯出。
- 透明 PNG 下載直接使用簽名網址的原檔。
- 收藏卡尺寸待 D-14（常見選項：1080×1080 正方形、1080×1350 直式、1080×1920 限時動態）。

## 7. 圖片權限驗收（摘自 09）

- [ ] 未登入者直接開 `character-art` 物件公開網址 → 失敗。
- [ ] 已登入但未解鎖 fm002 的玩家，對 `fm002/full.png` 要求簽名網址 → 拒絕。
- [ ] 解鎖 fm001 後 → 可取得簽名網址並顯示。
- [ ] 簽名網址過期後 → 無法開啟。
- [ ] 前端打包後的 JS 中搜尋不到任何正式插畫路徑清單或配方內容。
