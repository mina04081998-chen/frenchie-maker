# 09｜第一版 MVP 開發順序與測試驗收表

## 1. 開發階段

每個階段完成並經你驗收後，才進入下一階段。

| 階段 | 內容 | 前置條件（需要你提供／決定） | 驗收方式 |
|---|---|---|---|
| **Phase 0** | 本規劃文件 | — | 你確認文件與待決策 |
| **Phase 1** 前端原型 | Vite + React + TS 專案；所有頁面畫面與流程；使用**假資料**（假配方在原型中可見，Phase 2 移除）；手機版面 | D-12、D-18、D-20；第一批示意圖（可先用草圖） | 手機瀏覽器點完整流程 |
| **Phase 2** 資料庫與帳號 | Supabase 專案；migration；GRANT/RLS；Auth（註冊、登入、登出、重設密碼）；profile；匯入工具；初始元素 | 測試角色 PNG、三份 CSV、D-01～D-03、D-10、D-19 | 權限自我檢查全部通過 |
| **Phase 3** 核心玩法 | `craft()`；元素扣料；圖鑑解鎖；私有圖片簽名讀取；每日領取 | D-04～D-09、D-11、D-21 | 下方測試表 T-CRAFT、T-DAILY、T-IMG |
| **Phase 4** 訪客試玩 | 試玩模式（練習元素、投料動畫、只看剪影） | D-32 | T-GUEST |
| **Phase 5** 分享與個人化 | 頭像上傳；透明 PNG 下載；收藏卡 | D-14、D-15、Logo | T-SHARE |
| **Phase 6** 上線準備 | 部署；自訂 SMTP；錯誤監控；手機實機測試 | D-16、D-18、D-19 | 全部測試表回歸一次 |

> Phase 1 先做前端原型，是為了讓你盡早在手機上看到畫面、調整體驗；真正的規則在 Phase 2、3 移到伺服器。
